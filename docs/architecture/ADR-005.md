## Context

The Model Context Protocol (MCP) defines how AI agents interact with external tools. mac-control-mcp exposes macOS **observation** capabilities as MCP tools. The tool interface must balance expressiveness with security, token efficiency, and reliability — and must not duplicate cua-driver.

## Decision

### Division of labor with cua-driver

mac-control-mcp is **read-only for input** (never posts clicks/keys). cua-driver owns the action layer and its own window-mapped AX snapshot. This server fills the gaps:

| cua-driver blind spot | mac-control-mcp tool |
|---|---|
| Window-mapped AX returns empty for Catalyst / iOS-on-Mac / AppleSystemUIService | `ax_snapshot(app=...)` (raw, by app name) |
| No way to read text from AX-empty surfaces | `screen_capture` + `screen_ocr` |
| No AppleScript/JXA layer | `osa_search`, `osa_run`, `osa_exec` |
| No Apple-app data access | Mail / Calendar / Reminders / Notes / Messages / Contacts / Finder / QuickLook |
| No Spotlight / mdfind | `spotlight_query` |

### Tool Categories

**1. AX (Accessibility) — 1 tool** (read-only snapshot)

| Tool | Purpose | Returns |
|------|---------|---------|
| `ax_snapshot` | RAW AX tree traversal by app name (works where cua-driver's window-mapped AX can't bind) | JSON with roles, labels, values, coords |

**2. Vision — 2 tools**

| Tool | Purpose | Returns |
|------|---------|---------|
| `screen_capture` | Screenshot as base64 | Data, format, dimensions, size |
| `screen_ocr` | OCR from region or base64 image (on-device Vision.framework) | Text + observations with confidence + bbox |

**3. OSA (AppleScript/JXA) — 3 tools**

| Tool | Purpose | Returns |
|------|---------|---------|
| `osa_search` | Fuzzy search the YAML KB for AppleScripts | Ranked entries with IDs |
| `osa_run` | Execute KB script by ID with args | Script output |
| `osa_exec` | Execute raw AppleScript/JXA (destructive patterns forbidden) | Script output |

**4. Apple Apps — 17 tools**

Mail (`mail_search`, `mail_recent`, `mail_send`), Calendar (`calendar_events`, `calendar_create_event`), Reminders (`reminders_list`, `reminders_add`), Notes (`notes_search`, `notes_get`, `notes_create`), Messages (`messages_recent`, `messages_send`), Contacts (`contacts_search`), Finder (`finder_tags_get`, `finder_tags_set`, `quicklook`), Spotlight (`spotlight_query`).

### Design Principles

1. **Observe, don't act:** coordinates returned by `ax_snapshot` and OCR bboxes are passed to **cua-driver** for background clicks — this server never posts input.
2. **Token budget:** AX trees default to 12K chars. `prune_tree` + `trim_to_budget` control output size. Agents can override `budget_chars`.
3. **Security-first OSA:** `osa_exec` forbids destructive patterns. `osa_run` uses vetted KB entries. `check_osa_script()` validates at execution time.
4. **KB pattern over raw scripts:** Agents call `osa_search` → `osa_run` rather than writing AppleScript from scratch. YAML KB is the single source of truth for Apple app automation.
5. **Filtered at OS layer:** Calendar, Mail, Reminders queries accept date predicates that are pushed to the OS — no full data dumps.
6. **Fallback OCR:** Vision.framework OCR via pyobjc (fast) falls back to AppleScript-based OCR (compatible) when framework unavailable.

### Removed tools (cua-driver owns, or brittle/retired)

- `ax_click`, `ax_type`, `ax_scroll`, `ax_hotkey` — global CGEvent taps that steal focus; cua-driver does backgrounded action with no focus steal.
- `ax_system_ui` — Spotlight/menu-bar/Control Center/Launchpad via brittle osascript string interpolation; cua-driver drives menu bars natively.
- `screen_list_windows` — cua-driver `list_windows`.
- `screen_wait_for_change` — MD5-whole-screenshot heuristic; cua-driver verify-by-resnapshot loop.
- `check_ssrf` — dead code (never called).

### Transport

- **Protocol:** JSON-RPC 2.0 over stdio
- **Entry point:** `mac-control-mcp` CLI via `__main__.py` → `server.run(transport="stdio")`
- **No HTTP endpoint** — server designed for local/sidecar execution

## Consequences

- 23 total tools covering the read-only macOS observation surface, complementing cua-driver
- KB pattern reduces LLM-generated script errors — search + execute known-good scripts
- OCR/bbox/AX-frame output feeds cua-driver clicks without focus steal
- Security guards prevent accidental destructive operations
- Token budgets prevent context window overflow from large AX trees
